# Linker Eval & Iteration — Guide for Future Sessions

This folder is the **dev/analysis harness** for the SKU-matching algorithm (the
`#/link` and `#/link-rapid` tools). Nothing here runs in `run_daily.sh` — it's all
run by hand against the `.worktrees/data` worktree while iterating on the scorer.

## The one rule that matters

The **single source of truth for scoring** is
`viz/app/linker_page/suggestions.js::scorePairWithVocab` (+ its helpers in
`similarity.js`, `vocab.js`, `concepts.js`, `size.js`, `price.js`). Both the live
ranker (`recommendSimilar`) and every tool here **import that same function**, so
eval and production can never drift. Never fork scoring logic into a tool.

## Files

| File | What it is |
|---|---|
| `TECHNICAL_REPORT.md` | **Canonical spec** of the scorer: pipeline, every factor & formula, the full constants table, and the running list of techniques. Update it whenever the scorer changes. |
| `CLASSIFIER_PLAN.md` | Roadmap for a future learned classifier (log-linear blend of the existing factors, embeddings for semantic matches). Not built yet. |
| `../linker_eval.mjs` | **Benchmark harness.** Run on every scorer change. Prints the metric tables + worst FP/FN. Writes `pairs.json` + `last_run.json`. |
| `../linker_outliers.mjs` | **Label-QA / disagreement report.** Scores *every* link & ignore; writes `outliers.json` + `algo_failures.md` (factor-decomposed). Run it to find what to fix next and to spot mislabels. |
| `pairs.json` | Last run's scored pair list — the next `linker_eval` run diffs against it and prints score movements >0.5. |
| `last_run.json` | Headline numbers from the last run (AUC+, etc.). |
| `algo_failures.md` | Human-readable worst disagreements (regenerated by `linker_outliers.mjs`). |
| `runs/` | Archived historical run logs. |

There is **no `fixtures.json` anymore** — it was deleted. Evaluation is entirely
against the live `data/sku_links.json` (links = positives, ignores = curated hard
negatives), which is large and keeps improving.

## How to run

```bash
node tools/linker_eval.mjs       # metrics + worst FP/FN  (~seconds)
node tools/linker_outliers.mjs   # regenerate algo_failures.md / outliers.json
```

Both read `.worktrees/data/viz/data/index.json` and
`.worktrees/data/data/sku_links*.json`. Override with `DATA_WORKTREE=...`.

## The metrics that matter (and the ones that don't)

- **AUC+ = AUC vs auto-mined HARD negatives** (pairs sharing a distinctive bigram,
  different canonical group). **This is the headline number.** A trivial
  "share-any-word" baseline is printed beside it as the floor (~0.51 — i.e. no
  signal); AUC+ measures real discrimination above that.
- **Auto-link threshold table** — the operational number: the score cutoff that
  hits 95% / 99% precision (positives vs ignores+hard) and the recall there.
- **AUC vs random is meaningless** (~1.0 for any non-broken scorer) — ignore it.
- The old "auto-link precision ceiling" (a small-fixture metric) is retired.

## How to REPORT results to the user (required format — see root CLAUDE.md too)

Do **not** paste raw harness text. Re-render as **Markdown tables** with headers,
**all rows** (e.g. all 15 worst offenders): (1) headline metrics, (2) 15 worst
false positives `# | Algo | Expected | SKU A | Name A | SKU B | Name B | Why`,
(3) 15 worst false negatives, same columns. Prose analysis before/after is welcome.
Flag suspected mislabels explicitly so they get relabeled, not chased.

## The iteration loop (how every improvement this far was made)

1. `node tools/linker_outliers.mjs` → read `algo_failures.md`: the worst
   **over-scoring** (ignores scored high = false positives) and **under-scoring**
   (links scored low = false negatives).
2. Pick a failure *class* (e.g. "flavored variants", "SMWS codes", "size variants").
3. **Measure the false-negative RISK before adding any discriminator.** Write a
   quick script over the labeled groups: "how many confirmed-link groups would this
   rule break?" A rule that breaks many positives is not safe (see the table below).
4. Implement behind `scorePairWithVocab`; re-run `linker_eval.mjs`.
5. **Keep it only if AUC+ holds or rises** and the targeted cases moved. A change
   that helps a few cases but lowers AUC+ is collapsing signal the hard-negatives
   need — revert it (this killed the token-level levenshtein canon).
6. Spot-check controls (a few known true links must stay high) and re-run outliers.

## Hard-won lessons (don't re-learn these)

- **Labels lag reality.** Hundreds of links/ignores are still unadded. Treat the
  current set as ground truth, assume it keeps improving, and **don't tune to the
  unlabeled middle.** Many "false positives" in the reports are real matches not yet
  linked.
- **A discriminator is only safe if stores label it consistently.** Measured
  false-negative breaks per idea:
  - category (gin/rum/whisky), single-barrel↔small-batch, non-alc, maturation
    (blanco/reposado/añejo), shared-SMWS, mid-word-cut → **~0 breaks → hard rules.**
  - whisky substyle (rye/bourbon/single-malt) → ~9 breaks, mostly mislabels → moderate.
  - **cask strength (30), sherry (19), one-sided age (170)** → stores *omit* the
    qualifier for the SAME product → **NOT safe as hard rules.** Cask-strength/sherry
    are gentle nudges only; one-sided age is left alone. ABV (when both sides state it)
    is the real lever for strength.
- **"blend"/"blended malt" are used interchangeably** in this catalog — excluded from
  the substyle wall (unlike malt↔rye, which is consistent).
- **The IB/distillery confusion** (Signatory Caol Ila ↔ Signatory Laphroaig) was fixed
  *automatically* by lowering the distinctive-IDF threshold ι 5.5→4.6 — those entity
  tokens sit at idf ~4.6–5.2, just under the old cutoff. Swept empirically; AUC+ peaks
  at 4.6. No gazetteer needed.
- **SMWS / spaceless-core / mid-cut use score FLOORS, applied last** so a definitive
  match (shared cask code, identical core, truncated title) can't be buried by other
  penalties. SMWS names are often flavor tasting-notes, so ordering matters.
- **Token-level fuzzy canonicalization (levenshtein/prefix) does NOT help** — tested,
  it lowered AUC+ by collapsing tokens the hard-negatives rely on. The *narrow*
  mid-word-cut (strict prefix of the last token only) is the safe subset and is kept.
- **Edition-code conflict must DOMINATE a shared code** (`editionCodeMultiplier`, 2026-05-29):
  a shared `year:1997` was masking a conflicting `season:s22` vs `s24` → returned a 1.15 boost
  instead of penalizing (Glenfarclas Family Casks scored as matches). Now `conflictAny → 0.1`
  is checked BEFORE `sharedAny → 1.15`. FN-risk 6/3415 = 0.18%, all themselves mislabels
  (Lagavulin DE 2020↔2022, GlenDronach 2011↔2013) → safe.
- **Year-as-size misparse fixed** (`size.js`, 2026-05-29): a URL slug like `…-2023-ml-…` parsed
  `2023` as a 2023 mL bottle → spurious size conflict that killed real links (HP Cask Strength).
  `parseSizesMlFromText` now rejects a 4-digit value in [1900,2099] when the unit is `ml`.

## What's left (the residual, per the reports)

Mostly intrinsic / needs non-text signal, not more rules:
- **Cross-store size variants** the name omits and price can't separate.
- **Synonym brands** (`Compass Box Artist` = `Great King Street Artist's Blend`) —
  would need a brand-alias entry.
- The real next lever is in `CLASSIFIER_PLAN.md` / `TECHNICAL_REPORT.md §8`:
  price-availability time-series correlation, shared provider IDs — independent of
  name text. (Investigated: cross-store image/URL IDs are NOT shared in this catalog.)

## Editing data (mislabels)

`data/sku_links.json` is minified single-line JSON on the `data` branch worktree and
**carries important uncommitted human edits** — never reformat it. To remove bad
links: back it up, parse → filter the exact `{fromSku,toSku}` edges → re-`JSON.stringify`,
verify a round-trip is byte-identical except the removed objects, and confirm the
groups split as intended (see prior removals for the pattern). Cut only the bridging
edge(s); keep correct within-product links.
